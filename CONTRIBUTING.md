# Правила разработки и работы с Git

## 1. Именование веток

Все новые изменения разрабатываются в отдельных ветках. Имя ветки должно начинаться с префикса:

* `feature/` (или `feat/`) — для разработки нового функционала (например, `feature/docker-setup`, `feature/auth-jwt`).
* `bugfix/` (или `fix/`) — для исправления багов (например, `bugfix/db-connection-timeout`).
* `hotfix/` — для критических правок на production.

---

## 2. Формат коммитов (Conventional Commits)

Формат сообщения коммита:
`<тип>: <краткое описание на русском или английском>`

### Основные типы:

* `feat:` — новый функционал (`feat: add docker-compose with postgres`)
* `fix:` — исправление ошибки (`fix: correct db host in settings`)
* `docs:` — изменения в документации (`docs: add docker run instructions`)
* `refactor:` — правка кода без изменения функциональности
* `style:` — форматирование, отсутствующие точки с запятой и т.д.
* `test:` — добавление или правка тестов
* `chore:` — обновление зависимостей, сборки, конфигов (`chore: update Makefile`)
